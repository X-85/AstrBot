# AstrBot 文件替换说明

> 本包基于**服务器容器原版代码（4.27.2-20260805）**重建，只含业务修改，不引入镜像里没有的新模块。
> 文件组成：
> - `observability/` 2 个文件：**新增**，是 `astrbot_plugin_message_trace` 插件的核心依赖（自包含，仅依赖 `astr_message_event`）；
> - `dingtalk_adapter.py`：**整文件替换**，容器原版 + 历史业务修改（sessionWebhook 回推/@ 高亮、昵称/工号持久化、群会话登记）；
> - `knowledge_base_tools.py`：**整文件替换**，容器原版 + 注入详情调试打印。
>
> ⚠️ 注意：本包**不包含** `astr_main_agent.py`、`tool_loop_agent_runner.py`——容器原版已满足需求（差异仅为 trace 插桩），无需替换。

## 容器内目标根目录

AstrBot 仓库根在容器内通常为 **`/AstrBot`**（docker 部署常见路径）。
若你的容器实际挂载/安装路径不同，请把下表里的 `/AstrBot` 前缀替换成实际仓库根。

## 文件替换位置

| 操作 | 本包相对路径 | 容器内目标路径 | 说明 |
|------|--------------------------|----------------|------|
| 新增 | `astrbot/core/observability/__init__.py` | `astrbot:/AstrBot/astrbot/core/observability/__init__.py` | 导出 trace sink API（message_trace 插件依赖） |
| 新增 | `astrbot/core/observability/message_trace.py` | `astrbot:/AstrBot/astrbot/core/observability/message_trace.py` | 核心→插件的 trace 发射器 |

## 使用方式

把整个 `deploy/` 目录（含 `astrbot/`、`replace.sh`、`rollback.sh`、本说明）上传到服务器，例如 `/home/ymsk/astrbot-bak/deploy`：

```bash
# 1. 创建/启动容器（你的原始 docker run 命令）
# 2. 一键备份 + 替换 + 重启
cd /home/ymsk/astrbot-bak/deploy
sudo bash replace.sh
```

脚本执行流程：

```
[bak]  /AstrBot/astrbot/core/... -> astrbot-bak/astrbot/core/...   ← 先把容器内原文件备份出来
[!!]   容器内不存在 ...（新增文件），跳过备份                        ← observability 两个文件会走这行
[ok]   -> /AstrBot/astrbot/core/...                                 ← 再替换/新增
[done] 已重启容器
```

- 新增文件（`observability`）会自动先创建容器内目录再拷贝；
- 备份默认存到 `deploy/astrbot-bak/`，目录结构与容器内路径对齐（如 `astrbot-bak/astrbot/core/...`）。

验证生效：

```bash
docker exec astrbot bash -c \
  'grep -n "你的改动标志字符串" astrbot/core/platform/sources/dingtalk/dingtalk_adapter.py'
```

## 回滚

替换后如果 AstrBot 起不来或行为异常，用备份一键还原：

```bash
cd /home/ymsk/astrbot-bak/deploy
sudo bash rollback.sh
```

`rollback.sh` 会把 `astrbot-bak/` 里的文件拷回容器并重启。注意：备份里没有的文件（即新增文件，如 `observability`）不会被删除，如需完整还原需手动处理。

## 注意事项

1. **容器重建后需重跑**：`docker cp` 写入的是容器可写层，`docker rm -f` 重建容器后会丢失，必须每次重建后重新执行 `sudo bash replace.sh`（重建后 `astrbot-bak/` 里是上次替换前的原文件，重跑会先重新备份新容器内的官方原版）。
2. **替换后必须重启**：AstrBot 是常驻 Python 进程，文件替换后要 `docker restart astrbot`（脚本已自动做）才会加载新代码。
3. **文件改动后重跑**：修改 `astrbot/` 下任何文件后，重新执行 `sudo bash replace.sh` 即可。
4. **不要整个目录覆盖**：只替换上表列出的文件，不要把 `astrbot/` 整个目录拷到容器里覆盖 `/AstrBot/astrbot/core`（会缺文件起不来）。
5. **持久化备选**：若要"重建容器也不丢改动"，可改用 `docker run` 的 `-v` 单文件挂载方式（每个文件一条 `-v`）。当前脚本是 docker cp 方式，够用且简单。
6. **上传前确认目录干净**：`replace.sh` 会把 `astrbot/` 下 `find` 到的**所有文件**都拷进容器。不要在本机跑 `py_compile` 后直接上传（会生成 `__pycache__/*.pyc` 被一并拷入），上传前确认没有 `__pycache__/` 等杂文件。
7. **Docker 权限**：如果执行报 `permission denied ... /var/run/docker.sock`，用 `sudo bash replace.sh`（或把用户加入 docker 组）。
