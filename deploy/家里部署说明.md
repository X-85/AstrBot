# AstrBot 文件替换说明（家里 Docker）

> 与《替换说明.md》（公司服务器版）配套：载荷、脚本、回滚逻辑完全相同，本文只写家里的差异项和已验证的命令。
> 家里环境：macOS + Docker Desktop，容器名 `astrbot`，镜像 `soulter/astrbot:latest`（daocloud 镜像源拉取），仓库根 `/AstrBot`。

## 与公司版的关键差异

| 项 | 公司 | 家里 |
|---|---|---|
| 载荷来源 | 手工上传 `deploy/` 目录到服务器 | `deploy/` 就在本地仓库，无需上传 |
| 执行方式 | `sudo bash replace.sh` | `bash replace.sh`（Docker Desktop 无需 sudo） |
| 脚本前置校验 | 无 | 先跑 `bash check-drift.sh`，确认载荷与分支一致 |
| 镜像版本 | 4.27.2-20260805（固定） | `latest` 标签，**拉取新版镜像后必须重跑 replace.sh** |

## 部署步骤

```bash
cd <仓库根>
bash deploy/check-drift.sh   # 必须输出 [ok]，否则先同步载荷
bash deploy/replace.sh
```

脚本会自动：备份容器内原文件到 `deploy/astrbot-bak/` → `docker cp` 替换 → `docker restart astrbot`。

## 验证（2026-08-30 首次部署实测通过）

```bash
docker logs astrbot --tail 50                      # 启动无异常、WebUI ready、钉钉 Stream 连接成功
docker exec astrbot bash -c \
  'grep -c "sessionWebhook" /AstrBot/astrbot/core/platform/sources/dingtalk/dingtalk_adapter.py'
# 预期 12
docker exec astrbot bash -c 'ls /AstrBot/astrbot/core/observability/'
# 预期 __init__.py message_trace.py
```

## 回滚

```bash
bash deploy/rollback.sh
```

细节同《替换说明.md》回滚一节（新增的 observability 文件不会被回滚删除）。

## 注意事项

1. **镜像升级后必须重跑**：家里镜像用 `latest` 标签，`docker pull` 更新镜像并重建容器后，补丁会随可写层一起丢失，必须重跑 `replace.sh`。
2. 公司版注意事项 1–7（容器重建后重跑、替换后必须重启、不要整目录覆盖、上传前目录干净等）全部适用，不再重复。
